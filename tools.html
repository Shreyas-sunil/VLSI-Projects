Toolchain setup

A reproducible, low-cost workflow. Commercial EDA tools are optional everywhere.

AreaRecommended toolsDocs
Simulation and verificationVerilator, Icarus Verilog, cocotb; SystemVerilog classes need Questa Intel FPGA edition, Aldec Riviera (EDA Playground) or a commercial simulator; SymbiYosys for formal.link
Synthesis and FPGAYosys with nextpnr for supported FPGAs; Vivado for Xilinx devices (free edition for some parts, check current terms).link
Physical designOpenROAD-flow-scripts or OpenLane with the sky130 PDK; NanGate45/FreePDK45 are alternatives matching the 45 nm lab wording.link
Analog and layoutxschem, ngspice, Magic or KLayout with sky130; Monte-Carlo via ngspice. sky130 is not RF-characterised, so treat RF numbers as indicative.link
Embedded and firmwarearm-none-eabi-gcc or riscv-gcc, OpenOCD/GDB, QEMU or Renode, FreeRTOS. Emulators do not give true timing.link
CUDA / GPUCUDA toolkit and Nsight Compute on any supported NVIDIA GPU. Without one, run only CPU stages locally and use a hosted GPU notebook if available; CPU/OpenCL substitutes are not CUDA results and must be labelled.link
Architecture modellingTimeloop/Accelergy, BookSim 2, GPGPU-Sim or Accel-Sim for GPU modelling (GPU-simulator setup is non-trivial).link
Data and MLPython, NumPy, SciPy, scikit-learn, PyTorch (CPU is enough for the small models used here).link

Hardware you may not have

  • FPGA board: optional. Use Verilator plus Yosys/Vivado reports and label results accordingly.
  • NVIDIA GPU: only needed for projects marked with the CUDA note. A hosted GPU notebook is a valid way to get real CUDA numbers where available; CPU or OpenCL stand-ins are not equivalent.
  • Commercial EDA: not needed. The open flow (Yosys, OpenROAD, ngspice, Magic) covers every project.
  • Fabrication: none required; GDS from the open flow is a layout artifact, not silicon.

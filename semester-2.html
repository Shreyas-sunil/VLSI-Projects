MVE321IA-P1Two-Stage Miller Op-Amp: Spec to Post-Layout in sky130 Track AIntermediateBuild first 5-7 wk22/30

Identification

Analog IC Design (MVE321IA), Semester 2. Level: Foundational. Primary track A; secondary: C. Estimated effort: 5-7 weeks (about 60-84 focused hours at roughly 12 h/week).

Syllabus mapping: Units II, III: op-amp topologies, compensation; Practicals 7, 9, 10

Engineering problem

Hand-calculated sizing rarely survives simulation, and layout parasitics erode phase margin. The project closes the loop from specification to post-layout.

Proposed solution and architecture

Size a two-stage Miller-compensated op-amp from specs (gain, GBW, PM, power), simulate DC/AC/transient/corners in ngspice, draw layout in Magic or KLayout with matching care, extract parasitics, and compare pre- and post-layout.

Spec sheet→Hand sizing (gm/Id)→ngspice testbenches→Layout→PEX→Corner report

Implementation plan

  1. Study: Razavi two-stage design, Miller compensation. Gate: derive GBW and PM relations.
  2. Size: by gm/Id; Gate: DC operating point as designed.
  3. Simulate: AC loop gain, PM, slew, noise, corners. Gate: spec table.
  4. Layout and extract: Gate: DRC/LVS clean.
  5. Compare pre/post-layout; document margins.

Tools and resources

xschem, ngspice, Magic/KLayout, sky130 PDK (all free). Optionally Cadence/Synopsys (not required).

Measurable evaluation

  • Baseline: Your hand-calculation prediction.
  • Measure: DC gain, GBW, phase margin, slew rate, power, input noise, offset (MC).
  • Success looks like: Meets stated specs at TT and across corners; post-layout degradation quantified.

Report each number as measured, simulated, analytical estimate or design target. Nothing here is a pre-measured result.

Final deliverables

Schematics, layout, testbenches, report.

Career value

Competencies: Analog design flow, compensation, layout parasitics.

Resume bullet (use only after you build it and fill in measured numbers): Designed a two-stage op-amp in sky130 and quantified post-layout vs pre-layout phase margin.

Likely interview questions:

  • Why Miller compensation?
  • What is the RHP zero?
  • How does layout affect PM?
  • How did you choose gm/Id?

Risks and fallback

Corner failures. Fallback: relax specs and document.

Extensions

  • Add CMFB for fully differential
  • Auto-sizing script

Proposed solution and architecture

Identification

Analog IC Design (MVE321IA), Semester 2. Level: Advanced / research. Primary track A; secondary: C. Estimated effort: 8-10 weeks (about 96-120 focused hours at roughly 12 h/week).

Syllabus mapping: Unit III stability/feedback concepts; Unit IV regulators; connection to MVE212IA activity data

Engineering problem

Large di/dt events in accelerators cause voltage droop and timing failures. The question is how much droop a given PDN and workload produce and how to mitigate it.

Proposed solution and architecture

Extract per-cycle current estimates from RTL activity, model the PDN (R, L, C) in ngspice, compute droop for workloads, and evaluate mitigations: staggered start, decap sizing, and a clock-stretch behaviour model. Simulation-level study; related published work on di/dt management exists.

Activity extraction→PDN model→Droop simulation→Mitigation models→Trade-off analysis

Implementation plan

  1. Study: PDN impedance, di/dt. Gate: derive resonance.
  2. Build: current trace from simulation. Gate: energy matches power estimate.
  3. Build: PDN SPICE. Gate: impedance profile.
  4. Simulate: droop; mitigations. Gate: comparisons.
  5. Report assumptions.

Tools and resources

Verilator/VCD, Python, ngspice.

Measurable evaluation

  • Baseline: No mitigation.
  • Measure: Peak droop, droop duration, throughput loss from mitigation.
  • Success looks like: Mitigation Pareto.

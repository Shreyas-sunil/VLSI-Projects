MVE331TA-P3GPU-Accelerated Analytic Placement Kernels (HPWL and Density) in CUDA Track BResearch-gradeStretch 8-12 wk27/30

Identification

Algorithms for VLSI Design Automation (MVE331TA), Semester 3. Level: Advanced / research. Primary track B; secondary: C. Estimated effort: 8-12 weeks (about 96-144 focused hours at roughly 12 h/week).

Syllabus mapping: Unit III placement; parallel-algorithm view of Units II and IV

Engineering problem

Placement is a large optimisation. GPU acceleration is established (for example DREAMPlace, Lin et al., DAC 2019), so the contribution here is a learning implementation and kernel study.

Proposed solution and architecture

Implement a simple analytic placer on CPU (weighted-average wirelength plus density), then CUDA kernels for wirelength gradient and density smoothing; profile and measure speedup and solution quality.

CPU placer→WA wirelength kernel→Density kernel→Optimiser→Profiler
CUDA note: needs a CUDA-capable NVIDIA GPU supported by your installed toolkit, or a hosted GPU notebook. A CPU, OpenMP or OpenCL stand-in is a different programming model: use it to develop the algorithm, but label results as non-CUDA and do not present them as native CUDA performance.

Implementation plan

  1. Study analytic placement.
  2. CPU version.
  3. CUDA WL kernel.
  4. Density kernel.
  5. Quality and speed comparison.

Tools and resources

CUDA, Nsight, benchmarks. Needs NVIDIA GPU for CUDA stages; CPU/OpenMP stage otherwise (clearly different).

Measurable evaluation

  • Baseline: CPU implementation.
  • Measure: HPWL, overflow, runtime, speedup.
  • Success looks like: Comparable quality, measured speedup.

Report each number as measured, simulated, analytical estimate or design target. Nothing here is a pre-measured result.

Final deliverables

Code, profiling, report.

Career value

Competencies: GPU kernels for irregular problems, EDA.

Resume bullet (use only after you build it and fill in measured numbers): Implemented CUDA kernels for analytic placement and measured speedup vs CPU.

Likely interview questions:

Risks and fallback
